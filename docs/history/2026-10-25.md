## 1. プロトタイプの作成

### 何を作ったか
- 形式は、ブラウザで動く HTML/JS のテキストゲーム。ビルド不要で、ファイルを開くだけで動く。
- ゲームの核になるループ。
  - 1年の行動は3択(自分を高める / 労働に専念する / 子供を育てる)。
  - 世代交代。30〜35歳で出産し、45歳で跡継ぎを決め、子が16〜26歳で引き継ぐ。
  - 出稼ぎと結婚、手土産(新職業・上位職・収集アイテム)。
  - 職業11種、資産3分類(家・換金アイテム・仕事道具)、互助金庫。
  - 世帯の段階解放(10世帯×10年で+5世帯)、ランキング4部門(この端末内だけ)。
- データ(`data.js`)・ロジック(`engine.js`)・画面(`ui.js`)を分けた。職業はデータに1項目足すだけで増やせる形にした。

### 設計メモ
- **乱数は状態の中に持たせた**。セーブとロードの後でも同じ展開になり、テストで再現できる。
- **向き不向き(隠しパラメータ)は保存しない**。人物の seed と職業IDのハッシュから計算する。後から職業を足しても、既存の人物の向き不向きがそのまま決まる。
- **跡継ぎが継ぐ年齢は職業ごとに決めた**(農家16歳〜医者26歳)。会話の「子は16〜26歳、親は46〜61歳で引き継ぐ」という幅を自然に説明できる。
- **手土産の判定は「乱数を使わない部分」と「乱数の部分」に分けた**。縁談の画面で「この人は何を持ち帰りそうか」のヒントを出せる。

### 悩んだこと
- **世帯Aが建てた病院は、世帯Bの過去にもあるか**。会話では決まっていなかった。最初は「全世帯で共有(ある)」で作り、ユーザーに確認した。結論は「ない」で、後で作り直した(2章)。
- **手土産のしきい値**。最初は能力の平均45以上にしたが、自動プレイでは平均33〜37までしか育たず、アイテムや上位職が一度も出なかった。38 / 43 に下げ、調整用の定数にまとめた。
- **バランス**。農地は初期投資の回収がやや早く、2代目で年収が大きく伸びる。会話の「代を重ねるごとに収益が増す」には合うので、仮置きのままにした。

### 試してみてやめたこと / 見つけた不具合
- **縁談の候補を発生時に固定する方式**は不具合になった。別の世帯が先にその出稼ぎ帰りと結婚すると、古い候補が残って選べなくなり、その世帯が先へ進めなくなる。そこで、候補を毎回最新に絞り込む方式に変え、回帰テストを足した。
- **記録欄を全体で新しい順に反転する方式**はやめた。同じ年の中で「収入」が行動より上に出て読みにくかった。年は新しい順、年の中は起きた順に並べる形にした。

### 検証
- 仕様ごとの個別テスト42件と、複数シードの自動プレイ(約2200ターン)でエラーなし。
- 偽の DOM で画面を一通り操作した。
- 実ブラウザ(headless Chromium)のスクリーンショットで見た目を確認した。

## 2. 追加の要望への対応

### 何を更新したか
- **建物は年で効く**。建物・解放された職業・史跡・他世帯の現職による効果は、その年以降の世帯にだけ存在する。
  - 村の状態に「いつから」の記録(`jobYear` / `buildingYear`)を持たせた。
  - 古いセーブは、ロード時に新しい形式へ移行する。
- **無職スタート**。新しい世帯は職なしで始まる。最初の職は準備なしで選べる。無職の間は日雇い(年30万円)で暮らす。
- **ログイン**。
  - Python 標準ライブラリだけのサーバーを足した。担当は、アカウント、セッション、セーブ保存。
  - パスワードは PBKDF2 でハッシュ化して保存する。セッションのトークンもハッシュで保存する。
  - 別サイトからの書き込み(CSRF)と、ログインの総当たりを防ぐ対策を入れた。
  - 同時に別の画面で保存された場合は検知し、どちらを残すかユーザーが選べる。
  - ゲストの記録は、初回ログイン時に引き継げる。
  - サーバーなしで開いたときは、ゲスト(この端末だけ)として動く。
- **村の様子のイラスト**。
  - SVG で描き、輪郭を少しゆらして手書き風にした。
  - 家の数と格、施設、職業ごとの仕事場、史跡、舟、畑は、いまの村の状態から描く。
  - 住民は歩いたり仕事をしたりする。タップすると名前が出る。

### 設計メモ
- 「早い年に建てる」ケースの扱い。世帯Bが過去に学校を建てると、学校は「その年から存在する」ことになり、先に建てた世帯Aの時代にも前倒しで反映される。矛盾が起きない方向を選んだ。
- **互助金庫は時間で区切らず共有のまま**にした。お金は抽象的な村の財布として扱う。ユーザーの確認待ち。
- **村の絵は、いちばん進んだ時点の姿を描く**。世帯ごとの時間差は反映しない。

### 悩んだこと
- **ログインの実現方法**。もとは静的ファイルだけの構成だった。外部サービスを使わず、依存も増やさないために、標準ライブラリのサーバーを足す形にした。
- **イラストの重さ**。動く雲を手書き風フィルタの層に入れると毎フレーム再計算になるので、雲は別の層に分けた。

### 試してみてやめたこと / 見つけた不具合
- **スマホ幅で絵の縦横比を 4:3 にする案**はやめた。左右が切れて村名の看板が見えなくなった。全幅で 5:3 に統一した。
- **絵のレイアウト**。最初は、後ろ列の家と道沿いの仕事場がくっついて見づらかった。家の列を上げて間隔を取った。
- 実装中に変数名の衝突(構文エラー)があり、テストで見つけて直した。

### 検証
- サーバーのテスト11件、ゲームの個別テスト61件、複数シードの自動プレイ、画面の通し操作がすべて通った。
- 実ブラウザで確認したこと。
  - 登録してプレイし、端末のデータを消して再読み込みしても、サーバーから復元される。
  - 誤ったパスワードを拒否する。
  - ログアウトとログインができる。
  - ファイルとして直接開いたとき、ゲストとして動く。

## 3. 難易度の調整・遺伝・世帯数の段階

### 何を更新したか
- **成長を控えめにした**。
  - 自分を高める 4.0→2.8、子育て 4.5→3.2、労働のついで 1.2→0.8。
  - 子供の自然な伸び 平均0.8→0.55/年、才能の開花 +6〜10→+4〜7、都会で身につく分 +3〜9→+2〜6。
  - 係数は `GROWTH` にまとめ、あとから調整しやすくした。
- **遺伝**。
  - 子は、両親の能力の「比率」(平均に対する偏り)を受け継ぐ。生まれたときの能力も、毎年の自然な伸びも、その偏りに沿う。
  - 得意な分野は、育成で伸ばすときにも少し伸びやすい(偏りの平方根をかける)。
  - 偏りがはっきりしている子には「頭脳の素質」などの札がつき、誕生時の記録にも「両親に似て〜」と出る。
- **世帯数の段階**。最初は5世帯。5→10→20→30と増え、30までが無料。上限を広げると、その先も10世帯ずつ増える。
  - 条件は従来どおり、全世帯が「世帯数と同じ年数」だけ進むこと。
- **手土産のしきい値を合わせ直した**。アイテムは能力の平均27以上、上位職は得意分野34以上かつ差9以上。

### 設計メモ
- **遺伝の強さ**は `INHERIT` にまとめた。
  - `bias: 0.8`: 親の偏りの8割を受け継ぐ。
  - `level: 0.08`: 親の能力の高さそのものも少し受け継ぐ。
  - `noise: 0.12`: 個人差。
- 偏りは平均1になるよう正規化している。全体の強さは変えずに、配分だけが変わる。
- 遺伝の偏りは隠しパラメータではなく、能力として見える。もともとある「向き不向き」(職業ごとの隠しパラメータ)とは別物として扱う。
- 古いセーブの人物には偏りの情報がないので、「偏りなし」として扱う。

### 結果(自動プレイでの計測)
- 当主の能力の平均(中央値)は 35→26、得意な能力の最大値は 47→38。おおよそ25〜30%控えめになった。
- 職業の条件を満たせる当主の割合も下がった。教師は約35%→約15%、鍛冶屋は約55%→約10%。医者は以前から、自動プレイではほぼ届かない。

### 悩んだこと
- **手土産の判定順**。しきい値を下げたところ、「身体に特化した高能力の人」が「全体的に高い」扱いになり、上位職ではなくアイテムを持ち帰ってしまった。会話の仕様(特化→上位職、全体的に高い→アイテム)に合わせて、特化の判定を先にした。
- **しきい値の決め方**。自動プレイは親と同じ職の方向にしか育てないので、能力の分布が狭い。人が工夫して育てる前提で、アイテムは自動プレイの上位5%より少し上、上位職は上位1割ほどに置いた。実際に遊んでの調整が必要。

### やめたこと
- 遺伝を「子の能力 = 両親の平均の何割か」とする案は採らなかった。親が強いほど子が強くなる一方になり、成長を控えめにした意味が薄れる。そこで、強さではなく「比率(偏り)」を受け継ぐ形を主にした。

### 検証
- 個別テスト66件が通った。追加したテストは次のとおり。
  - 頭脳に偏った両親から頭脳寄りの子が生まれる。偏りのない両親からは偏りの小さい子が生まれる。
  - 世帯数が 5→10→20→30 と増え、30で止まる。上限を広げると40に増える。
- 自動プレイ・画面の通し操作・サーバーのテストも通った。実ブラウザで5世帯スタートと進捗の文言を確認した。
