## 毎日の訪問者の数を見る方法
- ユーザーが itch.io のページを作った(「Disable new downloads & purchases」は外してもらった。チェックがあると、遊ぶボタンのファイルが使えなくなるため)。
- ユーザーの質問: Supabase で、毎日どれぐらいの人が来ているか見られないか。
- 答え: Supabase に届くのは、ログイン・セーブ・ランキングなど、サーバーを使ったときだけ。ゲストはほとんどサーバーを使わないので、来た人の数は Supabase では分からない。分かるのはログインした人の数。
  - `supabase/daily_players.sql`(新規。snippets/ は Docker が作ったフォルダで書き込めなかった): Supabase の SQL Editor に貼る、読むだけの集計。日ごとの新しいアカウント・最後にログインした日・最後にセーブした日・全体の数(アカウント・セーブ・ランキングの村・この7日にログインした人)。auth.users は「最後のログイン」しか持たないので、毎日の利用者数そのものにはならない。
- 訪問者の数そのものは、Cloudflare Web Analytics(無料・cookie を使わない)で数えるのがよい。Pages の管理画面(プロジェクト → メトリクス → Web Analytics)でオンにすると、Cloudflare がページに計測のスクリプトを差し込む。
  - そのスクリプトが CSP で止められないよう、`build.mjs` の CSP に `https://static.cloudflareinsights.com`(script-src)と `https://cloudflareinsights.com`(connect-src)を足した(広告あり・なしの両方)。
  - プライバシーポリシーの Cloudflare の行に、アクセスの数の計測(cookie を使わず、個人を特定しない)を書き足した。改定日 2026年11月14日。
  - 組み立てて、CSP に入ったことを確かめた。
- ユーザーの作業: `npm run deploy` → Pages の Web Analytics をオンにする。
- ユーザーが開いたのは、Web Analytics の一般の始め方の画面(ホスト名を入れる → 計測のコードが出る)。進め方: ホスト名に `furusato-momoyoki.pages.dev` を入れて Done → 次の画面に出る計測のコード(`data-cf-beacon='{"token": "…"}'`)の token を教えてもらう。自動で入る表示なら、それで終わり。
- 準備: `build.mjs` に、設定 `cfBeaconToken`(32文字)があるときだけ、head に計測のスクリプト(static.cloudflareinsights.com/beacon.min.js)を足す処理を入れた。いまは空なので何も入らないことを、組み立てて確かめた。
- token(`ddbf23c9097849de82816a9646c0d79b`。ページに載る公開の値)をもらい、`worker/config.production.json` の `cfBeaconToken` に入れて組み立てた。head に計測のスクリプトが入った。
- 実ブラウザで、組み立てた CSP を付けて開き、計測のスクリプト(static.cloudflareinsights.com)が読み込まれ、計測の送信(cloudflareinsights.com/cdn-cgi/rum への POST)まで進むこと、エラーと CSP の違反が0件を確かめた(手元からの送信は止めた)。画面テストも通った。
