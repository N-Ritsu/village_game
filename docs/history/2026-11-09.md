# 2026-11-09 の作業履歴

## 公開できた・バナー広告の相談
- ユーザーが `env -u CLOUDFLARE_API_TOKEN -u CF_API_TOKEN npm run deploy` で公開できた(鍵が環境に残っていたのが原因だった)。
- ユーザーの質問: バナー広告を付けられるか。いまの訪問者数で、だいたいいくらになるか。
- 答えたこと(実装はまだ):
  - 付けること自体はできる。必要な作業: 広告の読み込みを許すようセキュリティの見出し(CSP)を広げる、プライバシーポリシーに広告と外部送信(cookie など)を書く、広告の置き場所を決める(遊ぶ画面・長老の案内と重ならない所。世帯一覧の下や画面の下など)。
  - Google AdSense は、`*.workers.dev` のような他社のサブドメインでは審査に通りにくいという報告が多い(公式の禁止の記載は見つからなかった)。独自ドメイン(年1,500円前後〜)を取ってから申請するのが無難。ゲームのページは文章が少ないので「内容が乏しい」と断られることもある。審査がゆるい国内の広告(忍者AdMax など)も選択肢。
  - 収入の目安: 1回の訪問で画面を読み込むのは1回だけ(ページを切り替えない作り)なので、広告の表示は訪問の数とほぼ同じ。1,000回表示あたり数十〜数百円とみると、月1,000訪問で数十〜200円、1万で数百〜2,000円、10万で数千〜2万円ほど。単価は広告会社・時期・端末で大きく変わる。
  - 訪問者数は、私の側からは見られない(ゲームに訪問者を数える仕組みを入れていない。Cloudflare と Supabase の管理画面の数字は、ユーザーのアカウントでしか見えない)。見る場所を案内し、数字を教えてもらうことにした。
- 追加の質問: 世帯・村の様子・ランキング・設定をそれぞれ別のページにしたらどうなるか。
  - 答え: タブを切り替えるたびにページを読み込み直すので、広告の表示回数は「訪問 × 切り替えの回数」まで増える。ただし、遊ぶ時間のほとんどは世帯の画面(1年進めてもページは変わらない)なので、増えるのは1訪問あたり2〜3倍ほどの見込み。すぐ離れるページの広告は単価が下がりやすく、収入は表示回数ほどには増えない。
  - 失うもの: 切り替えのたびに BGM が止まって最初から鳴り直す(ページをまたいで音を続けられない)、ファイルの読み込み直しで切り替えが遅くなる、村の絵の動きも最初から。
  - おすすめ: 訪問がまだ少ないうちは、遊び心地を崩してまで分ける価値は小さい。まず訪問者数を確かめてから決める。

## 1ページのまま、Google AdSense の広告を付ける準備
- ユーザーの依頼: 1ページのまま広告を付ける。Google AdSense の流れを知りたい。独自ドメインは取りたくない(取ったら更新が要るのかも知りたい)。
- 作ったもの(広告の番号を設定に入れるまでは、何も変わらない):
  - 設定(`worker/config.production.json`)に `adsenseClient`(ca-pub-…)と `adsenseSlot`(広告ユニットの番号)を足した。いまは空。
  - ビルド(`worker/scripts/build.mjs`): `adsenseClient` があるときだけ、
    - `index.html` の head に、審査用の目印(`google-adsense-account`)と広告の読み込み(adsbygoogle.js)を足す。
    - `ads.txt`(`google.com, pub-…, DIRECT, f08c47fec0942fa0`)を作る。
    - セキュリティの見出し(CSP)に、Google の広告の読み込み・枠・通信・画像・同意の画面(Funding Choices)を足す。番号が無いときは、これまでの厳しい設定のまま。
  - 画面(`js/ui.js` の `mountStatic`): 広告枠を `#app` の外(`index.html` の `#ad-root`)に、起動時に1回だけ置く。描き直すたびに広告を読み込み直すと、広告の決まり(勝手に読み込み直さない)に触れるうえ、ちらつくため。番号が両方そろっているときだけ出す。「広告」の小さな札を付けた。
    - 合わせて、画面の下の欄(規約などのリンク)も `#footer-root` に移し、1回だけ描く。並びは、ゲーム → 広告 → 下の欄。
  - プライバシーポリシー: 取得する情報に「広告のための情報」、外部のサービスに「Google AdSense」、新しい節「4. 広告について(外部への情報の送信)」(送る情報・Google の使い方へのリンク・パーソナライズド広告を止める方法)を足した。改定日 2026年11月9日。
- 確かめたこと:
  - ゲームのテスト195件と画面テストが通った(画面テストは、下の欄が `#footer-root` に移ったことに合わせた)。
  - 作り物の番号(ca-pub-1234567890123456)で組み立てて、head の目印と読み込み・ads.txt・CSP を確かめた。実ブラウザで、その CSP を付けて開き、広告枠が1つだけ出る・タブを切り替えても同じ枠のまま(読み込み直さない)・ページのエラーと CSP の違反が0件を確かめた(Google への実際の読み込みは止めた)。
  - 本番の設定(番号が空)で組み立て直し、広告の読み込みも ads.txt も入らないことを確かめた。
  - 本物の広告が出るかと、Google の広告が CSP に引っかからないかは、番号をもらって公開してから確かめる(引っかかったら、ブラウザの開発者ツールに出る)。
- 作業環境: 新しい作業用フォルダで、Playwright 1.64.1 の仮想環境と libnss3・libnspr4 の展開を作り直した(ブラウザ本体は ~/.cache/ms-playwright の chromium-1248 が使えた)。
- 追加の質問: いくつかゲームを作っているが、後から複数申し込めるか。
  - 答え: AdSense のアカウントは1人1つが決まり(2つ目のアカウントは作れない)。ゲームごとに申し込むのではなく、同じアカウントの「サイト」に、ゲームのアドレスを1つずつ足す。サイトごとに審査がある。広告の番号(ca-pub-…)は全部のゲームで同じものを使い、広告ユニットをゲームごとに作れば、ゲームごとの収益も見られる。workers.dev の大もと(workers.dev)は自分のものではないので、ゲームごとのアドレスをそれぞれ足すことになる見込み(通りにくさも、ゲームごとに同じ)。
