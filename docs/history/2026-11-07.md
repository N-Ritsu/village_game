# 2026-11-07 の作業履歴

## ランキングを、ほかのプレイヤーの村と比べる形にした
- ユーザーの質問: ランキングに「現在はこの端末の中だけで動くランキングです。比較用に並んでいる『サンプル』の村は仮のデータで、オンライン版では他のプレイヤーの村に置き換わります」と出る。もう公開しているのに、なぜ見られないのか。
- 答え: ランキングは、最初の試作(10-25)のときのまま、オンライン化していなかった。公開の準備(ログイン・セーブ・課金・出稼ぎの行き来)ではランキングを扱わず、この残りに気づいていなかった。仮の村8つ(`D.SAMPLE_VILLAGES`)と自分の村を並べていただけだった。
- 作ったもの:
  - データベース(`supabase/migrations/20261108000000_rankings.sql`):
    - 表 `rankings`: 1アカウント1行。村の名前と4部門の値。直接は読み書きさせない(だれの行かが分かる user_id を見せないため)。アカウントを削除すると一緒に消える。
    - `put_ranking`: ログインしている人だけ。ブラウザで計算した値なので、上限で切りそろえる(出稼ぎ10万人・金庫10億万円・職業60種・収集60個まで)。名前の制御文字を消す。
    - `get_rankings`: ゲストでも読める。各部門の上位(自分の行を除く、最大20件。画面は10件)と、「いまの自分の値」で数えた順位(自分より上の村の数+1)、村の数を返す。同じ値なら、先にその値に達した村が上。
  - 通信(`js/api.js`): セーブが成功したら、続けてランキングの値を送る(失敗してもセーブは成功のまま。次のセーブで送り直す)。`getRankings` を足した。
  - 仕組み(`js/engine.js` の `rankings(s, remote)`): ほかの村の上位に、いまの自分の村を、サーバーが数えた順位の位置に混ぜる。サーバーに届かないときは自分の村だけ。仮の村のデータは消した。
  - 画面(`js/ui.js` の `viewRank`): ランキングを開くたびにサーバーから読む(1分以内で、自分の値が変わっていなければ読み直さない)。「最新にする」ボタン。自分が11位より下なら、表の下に自分の順位の行を足す。案内の文は、ログイン中・ゲスト・読み込み中・読み込めない・手元(サーバーなし)で出し分ける。
  - 載るのは、ログインしてセーブした村だけ。ゲストは、ほかの村と比べた自分の順位は見られるが、ほかのプレイヤーには載らない。
- 弱いところ: 値はブラウザで計算して送るので、書き換えれば上限の範囲で偽れる(セーブの中身もブラウザのもの)。サーバーで検証するには、遊びの計算をサーバーでやり直す必要があり、今回はしていない。
- 確かめたこと:
  - ゲームのテスト195件(ランキングの5件を書き換えた)と画面テストが通った。
  - 実ブラウザで、サーバーの代わりに作り物の答えを返して、ランキングの画面を確かめた(PCとスマホの幅。読み込み中 → 表。11位より下の自分の行。サーバーがない手元では自分の村だけ)。エラー0件。
  - データベースのテスト(`test/test_db.mjs`)に、ランキングの13件を足した(ログインしていないと載せられない・上限で切りそろえる・1人1行・表を直接読めない・ゲストでも読める・user_id を返さない・順位の数え方・自分の行を除く・最大20件・アカウント削除で消える)。**まだ流していない**。手元の Supabase(Docker Desktop)が止まっていたため。
  - 配布用ビルドに入ることを確認した(公開はしていない)。
- ユーザーの作業: 本番のデータベースに `supabase db push`、画面の公開に `npm run deploy`。順番は、データベースが先(画面が先でも、ランキングに「読み込めませんでした」と出るだけで、セーブは壊れない)。すでに遊んでいる人の村は、公開後に一度セーブすると載る。
