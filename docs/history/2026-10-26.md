# 2026-10-26 作業履歴

## 1. 公開方法の検討(実装はまだ)

### 検討したこと
- **ゲスト版だけを静的サイトで公開する**(Cloudflare Pages / GitHub Pages / Netlify)。無料ですぐできる。ただし記録はブラウザの中だけで、ブラウザのデータを消すと失われる。課金も実質できない。決済の確認にはサーバーが要り、ブラウザ側の記録は書き換えられるため。
- **ログインまで含めて公開する**。候補は Cloudflare(画面: Pages、ログインと保存: Workers + D1)。無料で、アクセスがない間に止まることもない。代わりに `server.py` の役割を JavaScript で書き直す必要がある。
  - 無料枠でいちばん先に効く上限は「1日のデータベース書き込み(約10万行)」。
  - 当時の「1年ごとに自動保存」だと、1日1時間遊ぶ人で50〜100人ほどが目安だった。

### やめた案
- **Render の無料プラン**: しばらくアクセスがないと止まり、止まるたびに SQLite のファイルが消える。アカウントが消えてしまう。
- **PythonAnywhere の無料プラン**: 2026年1月に縮小され、サポートも終わった。期限切れの扱いもはっきりしない。
- **Streamlit への切り替え**: ボタンを押すたびにサーバーでスクリプト全体を動かし直すので、1年進めるごとに数百ms〜1秒ほど待つ。アニメーションも作りにくい。今は計算をすべてブラウザで行っていて待ち時間がない。この利点を捨てる理由がないので採らない。

## 2. 保存を「セーブボタン」方式に変更

### 何を更新したか
- **端末とサーバーの役割を分けた**。
  - 遊んだ内容は、毎年この端末(localStorage)に残す。
  - サーバーへの保存は、画面上部の「セーブ」を押したときだけ。
- 「セーブ」の横に「前回のセーブ：10月26日 18:47」のように日時を出し、小さく「未セーブ間データの保持は保証されません」と添えた。
- **サーバー**: セーブ本体を返さず「何番目のセーブか・いつのセーブか」だけを返す軽い確認(`GET /api/save/meta`)を足した。保存の応答にも日時を入れた。
- 開いたときの判定。
  - この端末の記録が、サーバーの最新セーブを元にしている → 端末の記録で続ける(通信は確認だけ)。
  - 別の端末で新しくセーブされていて、この端末はそのあと進めていない → サーバーのセーブを読み込む。
  - 両方で進めていた → どちらで続けるか選ぶ。
  - セーブしたとき、別の端末のほうが新しかった → 読み込むか上書きするかを選ぶ。
- ログアウトしても、端末の記録(未セーブ分も)は消さないようにした。アカウントを削除したときは消す。

### 設計メモ
- ユーザーの案は「端末の記録の日時と、セーブの日時を比べる」だった。そのまま日時で比べると、困ることが2つある。
  - 端末ごとに時計がずれていると、古いほうを新しいと判定することがある。
  - 「PCでセーブせずに遊ぶ → スマホでセーブ → PCを開く」と、PCの未セーブ分が黙って捨てられる。
- そこで比較には、サーバーが付ける「セーブ番号」を使った。端末側には「どの番号を元にしているか」と「そのあと進めたか」を残す。日時は表示にだけ使う。
- 書き込みは「セーブを押した回数」だけになった。1人が1日5回セーブするなら、Cloudflare の無料枠でも1万人を超えるまで書き込みの上限に当たらない見込み。

### やめたこと
- 「未セーブの進行があります」の表示と、未セーブのままページを閉じるときの確認は、ユーザーの判断で入れないことにした。代わりに、前回のセーブ日時と注意書きを出す。
- 以前の自動保存の仕組み(1年ごとに裏で送信・失敗したら再送・閉じるときの確認)は、すべて外した。

### 見つけた不具合
- 縁談が来ている状態でセーブし、衝突の確認画面が出ると、縁談の画面が隠れたまま再表示されなかった。セーブの処理が終わったら、決めることが残っていればその画面を出し直すようにした。

### 検証
- サーバーのテスト12件(セーブ番号の確認を追加)、ゲームの個別テスト66件、画面の通し操作が通った。
- 実ブラウザで、2つの端末(別々のブラウザ環境)を使って確認した。
  - セーブ前後の日時表示。
  - 未セーブのまま再読み込みすると、端末の記録で続く。
  - 別の端末のセーブを読み込む。
  - 両方で進めていたときに選べる。
  - セーブ時の衝突を上書きで解決する。
  - ログアウトしてからログインし直しても、未セーブ分が残る。

## 次の候補

- 課金状態を、セーブデータではなくアカウント側(サーバー)で管理する。

## 3. 世帯の記録に「村の出来事」を差し込む・資産カードの位置

### 何を更新したか
- 世帯の画面で、資産カードを記録の下に移した(並びは 行動 → 子供 → 記録 → 資産 → 歴代の当主)。
- 各世帯の記録に、**別の世帯による村の大きな出来事**を、その年に達したところで差し込むようにした。
  - 対象は、初めて就かれた職業ごとの出来事、建物、都会帰りの知恵で解放された職業、怪物マグロの史跡、村に初めて持ち込まれた品、新しい世帯の入植。
  - 職業ごとの言い回しを用意した(例: 商店店員→「村に初めての商店ができた」、農家→「村に初めての畑が拓かれた」)。
  - 見た目は、青い線・薄い青の背景・「〇〇家」の札。自分の世帯の出来事と一目で区別できる。
  - 1年進めて出来事の年に達したときは、青い通知(「村の出来事: …」)も出る。

### 設計メモ
- 出来事は村全体の記録(`milestones`)として、種類ごとに1件だけ持つ。各世帯の記録に書き込むのではなく、表示するときに混ぜる。あとから過去の出来事が増えても、矛盾なく表示できる。
- **「初めて」は年がいちばん早い世帯のもの**にした。世帯ごとに時間が別なので、A家が2010年に商店を開いたあと、B家が2004年に開くこともある。その場合はB家の出来事に置き換わり、2004年から見える。
- その世帯ができる前の出来事は出さない(あとから入植した世帯の記録が、昔の話で埋まらないように)。そのため、世帯に「始まった年」(`startYear`)を持たせた。
- 古いセーブは、建物・史跡・いま就いている職業から、出来事を作り直す。

### 悩んだこと・直したこと
- 「職に就いただけで、まだ1年も進めていない世帯」は、これまで「遊んだ世帯」に数えていなかった。その職の効果や出来事が出ないのは不自然なので、職を選んだ時点で遊んだ世帯として扱うようにした。

### 検証
- 個別テスト74件が通った。追加したテストは、出来事がその年に達するまで出ないこと、自分の出来事は出ないこと、「初めて」が前倒しされること、世帯ができる前は出ないこと、古いセーブの作り直し。
- 画面の通し操作が通った。実ブラウザで、A家が商店を開いたあとB家を進めると、記録に青色で出て通知も出ることを確認した。

## 4. 商店・漁師の収支、引き継ぎ時の所持金

### 計測(変更前)
1つの世帯をその職業だけで40年進めた(主に労働、子供がいれば3年に1度育てる、余裕ができたら仕事道具を買う)。30シードの平均。
- 漁師: 40年中、平均27年が赤字。40年目は平均−616万円。漁船の条件(腕力35・勇気35)が、成長を控えめにしたあとの能力では届かず、ずっと網だけで漁をしていた。
- 商店店員: 開業費40万円は最初の2年で回収でき、最も苦しい時期でも−6万円ほど。「最初はきつい」感じがなかった。

### 何を更新したか
- **商店店員**: 開業費を40→120万円に上げた。開業から2年は「常連客がつくまで」として、収入を5割・7.5割にした。基本収入は80→95に上げた。上位職の商店主も、開業費を300万円にして同じ立ち上がりにした。
- **漁師**: 基本収入を55→80にした。
  - 漁船は 400→350万円、条件を腕力28・勇気25 に下げた。
  - 嵐で出漁できなくなる勇気の目安を 55→45 に下げた。
  - 安い「漁網」(100万円・8年・収入+15)を足した。
- **引き継ぎ**: 跡継ぎが家を継ぐとき、所持金の半分を親の老後の生活費として差し引く。借金は半分にせず、そのまま引き継ぐ。記録にも「所持金の半分(〇万円)は〜の老後の暮らしのために残された」と出る。

### 結果(変更後、同じ計測)
| 職業 | 最も苦しい時期 | 赤字の年数(40年中) | 5年目 | 20年目 | 40年目 |
| --- | --- | --- | --- | --- | --- |
| 農家 | +48 | 0 | 196 | 187 | 1636 |
| 漁師 | +38 | 0.2 | 120 | 200 | 373 |
| 商店店員 | −78 | 4.5 | 21 | 210 | 831 |

- 商店は、開業直後に借金を抱え、4〜5年で返し終える。
- 漁師は赤字にならなくなった。伸びは農家より控えめで、年ごとの差が大きい(怪物マグロのような一発のある職業として残した)。

### 試してやめた案
- **商店の開業費150万円 + 基本収入80のまま**: 厳しすぎた。結婚後の生活費で利息すら払えず、40年中32年が赤字のまま抜け出せなかった。
- そこで、基本収入・開業費・立ち上がりの組み合わせを5通り試した。「最初は借金、5年ほどで黒字、長い目では他の職と並ぶ」になる 95 / 120万円 / 5割・7.5割 を選んだ。

### 検証
- 個別テスト79件が通った。追加したテストは、引き継ぎで半分になること、借金は半分にならないこと、開業費で借金になること、開業1年目の記録。
- 画面の通し操作と、自動プレイ(エラーなし)も確認した。

## 5. 「自分を高める」を分野選びに変更

### 何を更新したか
- 「自分を高める」は、職業ではなく **身体・頭脳・精神のどれか1つを選んで鍛える** 行動にした。選んだ分野の2つの能力だけが、労働のついでよりずっと大きく伸びる。
- 代わりに、その年は仕事をほとんど休む扱いにした。収入はいつもの約2割で、記録にも「収入はわずかだった」と出る。
- 分野を選ぶ画面には、いまの能力の値と、その分野を条件に使う職業・道具(例: 身体→大工、精神→漁船)を出す。
- これまでの「その職業を一度『自分を高める』で磨かないと転職できない」ルールは、なくした。転職は、就く条件を満たしていればできる。

### 釣り合いの計測
最初の当主(腕力は平均18.5)が、大工の条件(腕力30)に届くまで「自分を高める」だけを続けた場合で計測した。
- 1回の伸び 2.8 のとき: 平均11年、その間に平均−378万円の借金。収入を捨てる代償に対して、伸びが物足りなかった。
- 1回の伸び 4.0 のとき: 平均8年、平均−185万円。1年で、労働のついでに伸びる分の6〜7年ぶんが伸びる。こちらに決めた。
- 実際は労働と混ぜて進める前提。早く条件に届きたいなら借金覚悟で鍛える、という選択になる。

### 設計メモ
- 分野で鍛えても、両親から受け継いだ偏り(得意な能力ほど伸びやすい)はそのまま効く。
- 大人の「才能の開花」は、職業を目指して磨く仕組みと結びついていたので、この変更で起きなくなった。子供の開花(子育てで、向いている職業の方向に育てたとき)は残っている。

### 検証
- 個別テスト82件が通った。追加したテストは、選んだ分野が仕事より大きく伸びること、選ばない分野は伸びないこと、収入がわずかになること、条件を満たせば転職できること。
- 画面の通し操作、自動プレイ(エラーなし)、実ブラウザで分野を選ぶ画面を確認した。

## 6. 才能の開花を「跡継ぎの数年後・とても稀」に変更

### 何を更新したか
- 開花は **跡継ぎだけ** に起きるようにした。子育て中の開花(1回ごとに18%)はなくした。不向きな方向に育てたときの「身が入らない」という記録は残した。
- 跡継ぎを決めたときに1回だけ判定する。条件は、いちばん多く育てた職業が、その子にぴったり向いていること(向き不向き 1.25以上、3回以上育てた)。条件を満たせば **1%** で開花が決まる。
- 開花が決まると、**2〜4年後** のある年に、その職業の能力が一気に +12〜18 伸びる(以前は +4〜7)。
  - 記録に「才能が、ある日突然開花した！」と出る。
  - 年表と、他の世帯から見える「村の出来事」にも残る。
- 判定と予定の年は内部に持つだけで、画面には出さない。親も本人も、その日まで知らない。

### 設計メモ
- ぴったり向いている職業は、1つの職業あたり8人に1人ほど(向き不向きは0.5〜1.5の三角分布で、1.25以上は約12.5%)。
  - 方向を気にせず育てると、開花は千人に1人ほど。
  - 子供の欄の「手応え — 飲み込みが驚くほど早い」は、ぴったり向いている合図と同じ条件なので、それを見て方向を合わせれば1%になる。
- 跡継ぎを決めた直後に家を継ぐこともある。予定は人物に持たせたので、当主になったあとでも、その年が来れば開花する。
- 確率・条件・時期・伸び幅は `BLOOM` と `GROWTH.bloom` にまとめた。

### 検証
- 個別テスト89件が通った。追加したテストは次のとおり(確率を一時的に100% / 0%にして確かめた)。
  - ぴったりの方向なら開花が予定される。
  - 2〜4年後に一気に伸びる。
  - 記録と村の出来事に残る。
  - 向いていない方向では開花しない。
  - 子育ての途中では開花しない。
- 画面の通し操作と自動プレイ(エラーなし)も確認した。
