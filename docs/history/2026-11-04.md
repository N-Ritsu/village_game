## PVの背景が速すぎた原因・？の枠のシルエット・家系図の書き方

## PVの背景の速さ(本当の原因)・Remotion 版のPV
- ユーザーの指摘: 背景の速度がまったく変わっていない。
- 本当の原因: 撮るときの時計(Playwright の clock)は、install しただけでは止まらず、ふつうの速さで流れ続けていた。1コマ撮るのに実際の時間が0.3秒ほどかかるので、そのあいだも時計が進み、動画の中の動きは10倍以上の速さになっていた。2秒ぶん(60コマ)撮るあいだに、時計が23.7秒進んでいたことを測って分かった。前の回の「絵の合図を時計で進める」直しは正しかったが、その時計自体が流れていたので効いていなかった。
- 直したこと: `pv/record.py` で、時計を install したあとに pause_at で止め、1コマぶん(33ミリ秒)ずつだけ進めるようにした。60コマで時計がちょうど1.98秒進み、村人の動きもゲーム本体と同じ速さになった。書き出した動画を0.5秒おきに切り出して、村人が少しずつ歩く(前の版では0.5秒で並びが入れ替わるほど動いていた)ことも確かめた。
- 反省: 速さを、ページの中の時刻の進みだけで確かめていて、撮るのにかかる時間と時計の関係を確かめていなかった。今回は「撮るのと同じ進め方で、時計が何秒進んだか」と「書き出した動画の中の動き」の両方で確かめた。
- Remotion 版: ユーザーが PV 用のプラグイン(Remotion: React でプログラムから動画を作る)を入れたので、それに合わせて作り直した版も作った(`pv-remotion/`)。プラグインの使い方(スキル)は、この作業環境からは読み込めなかったので、Remotion の作法(すべての動きを「何コマ目か」から決める)で作った。

## ほのぼの版の手直し(家系図の離れた人・成長の札・村人の歩き)

  - 直し方: 家系図を最初に一度だけ測り、空白のぶん跡継ぎの枝を左へ寄せた(深い枝から順に)。寄せると、親の夫婦から下りる縦線が、横線の右へはみ出すので、横線をその真下までのばした。`pv-remotion/src/PV.jsx` の `tuck`。
  - ゲーム本体の家系図も同じ並べ方なので、同じ離れ方が起こりうる。今回はPVだけ直し、ゲーム本体は変えていない(ゲームに直す場合は、測って寄せる処理が要る)。

- (3) 村の絵を作ったあと、50秒ぶんを0.1秒刻み(ゲームの1コマの上限と同じ)で進めてから、映し始める(`Village` の `warm`)。成長の3つの場面と、締めの背景に使った。冒頭の「5人の貧しい村人」は、はじめの位置のまま。

## 締めの文字のちかちか・ハートが出ていなかった件・ゲーム側の家系図
- ユーザーの指摘: (1) 締めの画面のURLと「公式X」の文字をちかちかさせない。(2) ゲーム側の家系図も直す。(3) git の認証が通らないのを治す方法。
- (1) 原因(測って突き止めた):
  - まず「動画に圧縮したときのノイズ」を疑ったが、描画そのままの連続コマでも、同じ周期(13コマ出て、13コマ消える)で再現した。「出る強さ」の値を、ブラウザの中から取り出すと、1.0000…で安定していた(値の問題ではない)。
  - 背景の飾りやベール(うす白い膜)は「位置を持つ」要素で、2行の文字は「位置を持たない」ふつうの要素。ブラウザは、位置を持つ要素を、持たない要素の**上**に描く。出る強さ(opacity)が1未満なら、その要素は独立した層になって上に出るが、ちょうど1以上だと層にならず、ベールの下に隠れる。ばねの揺れで、ごくわずかに1を上下するたびに、上に出たり下に隠れたりしていた。
  - 直し方: 2行に `position: relative` を付けた。同じ形の場所(背景より手前に出す文字)がほかにないかも見たが、ほかは、動きの指定で層になっているか、位置を持つ要素なので問題なかった。
  - 気づけなかった理由: 静止画で確かめたとき、2150コマ目の画像にURLが出ていなかったのに、「題名と札が出ている」ことだけを見て、URLの行を見落とした。出ているはずのものが出ているかを、数えて確かめるべきだった。
- 見つかった別の不具合: 舞う飾りの「ハート」が、一度も描かれていなかった。`@remotion/shapes` の Heart は大きさを `size` ではなく `height` で受け取る。`size` を渡したので幅が NaN になり、ブラウザの記録に「NaN」のエラーが出ていた(ここから見つけた)。`height` に直した。
- (2) ゲーム側の家系図: 共有の `js/ftree.js`(`VG.ftree.tuck(root)`)を作り、`index.html` で読み込み、`js/ui.js` の `treeModal` で、家系図を描いたあとに呼ぶ。線の追加は `style.css`(`.fshift` `.fext`)。PVも同じファイルを使う(PV側の写しは消した)。
  - 位置は `getBoundingClientRect` ではなく `offsetLeft` で測る(家系図を開くときの拡大の動きに左右されない)。
  - 確かめたこと: ゲームのテスト189件・画面テスト(偽のDOM)が通った。実ブラウザ(Playwright・Chromium)で、長く遊んだ状態のセーブを読み込み、家系図を開いて確認した(PCの幅とスマホの幅)。武が跡継ぎの隣に寄り、線もつながる。開いたときは、最初の夫婦が真ん中に来るところまでスクロールするので、左に寄った枠の端は、左へスクロールすると見える(従来どおりの動き)。
  - ユーザーの作業: ゲームへの反映は `npm run deploy`(本番への反映はユーザーが実行する決まり)。
- 作業環境のメモ: ゲームのテストは `pip install mini-racer`(個別・画面テスト)と playwright(実ブラウザ)が要る。今回は使い捨ての仮想環境に入れた。

## ゲームにBGMと効果音を入れた
