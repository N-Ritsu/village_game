## 都会へ送る子の能力の上限を「合計」で見るように変更

### ユーザーとのやりとり
- ユーザーから「ずる対策が分からない」と質問があった。想定しているのは次のずる。
  - このゲームの計算はブラウザで動いているので、開発者ツールでセーブや送るデータを書き換えられる。
  - 自分の村だけなら本人が損をするだけだが、他の村との行き来が入ったので、書き換えた「全能力100の子」が、まじめに遊んでいる他のプレイヤーの縁談に流れてしまう。
  - 迎えた村は、遺伝や手土産でバランスが崩れる。
- あわせて「特化型ビルドが損をしないようにしたい」という要望があった。

### 問題だった点
- これまでは、能力の1つ1つに上限をかけていた(10世帯の組はどれも40まで)。そのため、合計は少ないのに1つが高い特化型ほど削られていた。

### 何を更新したか
- 上限を、6つの能力の**合計**で見るように変えた(`supabase/migrations/20261101000000_city_cap.sql`)。
  - 合計が上限以内なら、配分はそのまま通す。
  - 超えたときだけ、全部を同じ割合で縮める(どこに特化しているかの形は残る)。
  - ありえない値をはじくため、1つの能力にも、ゆるい上限だけは残した。
- 上限: 10世帯の組は合計220・1つ80、20世帯の組は260・90、30世帯以上は300・100。

### 上限の決め方(計測)
- 自動プレイで育てた子(30世帯の組): 合計は中央値142・95%が158以下・最大165、いちばん高い能力の最大は45。
- 極端に特化させた子: 強く偏った両親・立派な家・16年同じ方向に育成し、開花と都会での伸びを最大にした場合。合計は最大292、1つの能力の最大は83。
- この極端な特化型でも、30世帯以上の組なら削られない値にした。全部100に書き換えた子(合計600)は、確実に削られる。

### 検証
- データベースのテスト34件が通った。追加・変更したテストは次のとおり。
  - 特化型(腕力90→80、ほかはそのまま)は削られない
  - 全部100は合計220まで同じ割合で縮む
  - 合計を超えた特化型は、偏りの形を保ったまま縮む
- 本番の Supabase には、この定義と前日の「都会」の定義を、ユーザーが `supabase db push` で入れる。

## 世帯の絵・縁談の顔ぶれ・遠い親戚・家系図
### 何を更新したか
- **世帯の絵**: 世帯を開くと、村の様子と同じ手書き風の絵が上に出る。
  - 家: 格によって見た目が変わる。
  - 家族: 当主・配偶者・子供。子供は年齢で大きさが変わり、家の前を歩き回る。
  - 仕事道具: 農地(収穫できる区画は作物、超えた分は休ませた畑)、農業機械、漁船と海、漁網、店、大工の作業場、炉、画材、質屋の蔵、教材、診療器具。使っていない職の道具は箱。
  - 換金アイテム、収集品(宝箱と個数)。
- **縁談は4人**: ふつうは村の外の人4人。他の村から来た人がいれば、村の外の人1人と入れ替えて 3+1。自分の村の出身者もいれば 2+1+1。他の村の人・自分の村の出身者は、それぞれ1人まで。
- **遠い親戚**
  - 子が生まれるときに、両親の血筋とこの村・この家を受け継ぐ(血筋は12件まで)。
  - 都会へ送るときに、血筋とその子の番号も送る。
  - 他の村から迎えた人がこの村の血を引いていれば、「〇〇は△△家の遠い親戚だった！」の演出が出て、収集品「△△家の家系図」を持ってくる。収集のランキングにも数える。
- **家系図**: 「歴代の当主」に「家系図を見る」を付けた。
  - 各世代の当主・配偶者(どこの家から来たか)・子供全員と、子供の行き先(跡継ぎ / この村の〇〇家へ / 〇〇村の〇〇家へ / 都会で暮らしている / 今の年齢)を表示する。
  - 他の村での結婚は、便りが届いたときに、送った子の番号で家系図に書き込む。
- **データベース**(`supabase/migrations/20261102000000_city_roots.sql`): 都会の表に「血筋」と「送り出した村での番号」の列を足した。送る・引く・結婚する・便りの関数を、それを扱う形に作り直した。血筋は、形の違うものを捨て、文字列の長さをそろえ、12件までにする。

### 設計メモ
- 「大きくなりすぎないか」というユーザーの心配について。1つの家で記録するのは、各世代の当主と、その世代の子供の番号だけ。子供の詳しい情報は、もともと持っている都会の記録から引くので、何十世代でも軽い。
- 他の村に嫁いだ子の、その先の子孫は追わない(他のプレイヤーのデータのため)。その代わりに「遠い親戚」の仕組みで、何世代かあとに血がつながった形で戻ってくる。
- 村ごとに識別子(`village.uid`)を持たせた。村の名前は重なることがあるので、血筋の比較にはこちらを使う。
- 古いセーブ: 世代交代の記録に子供の情報がない世代は、跡継ぎだけを表示する。

- 決めたこと:

  - 方向は世帯に1つで、子供全員に共通(「子供を育てる」が子供全員をまとめて育てる仕組みなので、それに合わせた)。2人目・3人目が生まれたときも画面は出るが、今の選択に札が付いて一番上に出るので、変えないならそのまま選べる。

  - 縁談・跡継ぎの決定が出ているときは、そちらを先に出す。セーブの読み込みや世帯の切り替えのあとでも、まだ選んでいなければ画面が出る。

## 嫁いできた人が、元の職業のまま村で働く
- ユーザーの希望: 自分の村の出身・他の村の出身の人が嫁いできたら、元の職業を引き継ぎ、その収益と村への効果も持ち込む(大工なら、村に大工がいることになる)。代替わりのときには、ほかの村人と同じように引退させる。
- 決めたこと(ユーザーに確かめた):
  - 都会へ出た子は、いままでゲーム上で職に就いていなかった。「元の職業」は、生まれた家で育てられた職業(育成方針でいちばん鍛えられた職のうち、就く条件を満たすもの。なければ能力のいちばん合う職)にした。都会へ出るときに決めて、本人に持たせる。
  - ごく稀に、都会帰りの手土産で新しい職業を持ち帰ったときは、職の解放だけでなく、本人もその職で嫁いでくる(上位職の手土産も同じ扱い)。
  - 収入は、その職の基本収入を本人の技能で計算した**半分**(家事・子育ても担うため)。仕事道具・昇進はなし(当主の道具は当主の職のためのもの)。当主の行動(自分を高める年など)に関係なく、毎年働く。記録には「収入 91万円(うちサキの稼ぎ 35万円)」と出す。
  - 村の外の人(NPC)は職を持ち込まない。
- 村への効果: その職業は、結婚した年から村にあることになる(時間差の仕組みどおり、結婚より前の年の世帯には効果がない)。村に初めての職なら「村に初めての〇〇」の出来事にも残る。代替わりで引退すると、その職の効果はなくなる(当主の職と同じで、いま働いている人の職だけが効果を出す)。
- 他の村から来る人: 送り出した村の側で職業を決めてサーバーに一緒に送るように、データベースに「職業」の欄を足した(`20261103000000_city_job.sql`)。形の違う値(英小文字と _ 以外)はサーバーで捨てる。迎えた村にまだない職業(医者など)だったら、能力から村にある職を選び直す(他の村との行き来で、職の解放ができてしまわないように)。

## 互助金庫は自分で降ろす・換金アイテムの値段の幅を広げた
- ユーザーの作業: 本番のデータベースへの `supabase db push`(配偶者の職業の欄)が終わった。
- 互助金庫:
  - ユーザーの希望で、所持金がマイナスになっても、金庫から自動で払われないようにした。代わりに、自分で降ろせるようにした。
  - 「互助金庫に納める」のボタンを「互助金庫」にして、同じ画面で「納める / 降ろす」を選べるようにした。年には数えない。
  - 降ろせるのは残高まで。借金がなくても降ろせる。金庫は村のみんなのお金(どの世帯・どの年からでも使える)という、これまでの考え方に合わせた。
  - 迷ったこと: 「借金があるときだけ降ろせる」にする案もあった。ただ、世帯はすべて同じプレイヤーのもので、納めたお金を別の世帯で使うのが金庫の役目なので、制限はつけなかった(納めたことで名士になる特典なども、いまはない)。
  - 借金がある間は、毎年5%の利息がつく(これまでは金庫が空のときだけだった)。記録の利息の行に「互助金庫から降ろして返すこともできる」と添える。世帯の画面にも「借金が120万円あります…[互助金庫を開く]」と出す。
  - 金庫の画面では、借金があるときは金額の欄に借金の額を最初から入れておき、「借金の分」のボタンも出す。
  - 自動プレイは、借金ができたら自分で降ろして返すようにした(人が遊ぶときと同じ)。
- 換金アイテム:
  - ユーザーの希望で、100〜300万円の4種類から、200万円〜5億円の9種類にした。古い壺 200万 / 掛け軸 400万 / 金の延べ棒 800万 / 洋画 1500万 / 古伊万里の大皿 3000万 / 名工の日本刀 6000万 / 古い仏像 1.2億 / 金箔の屏風 3億 / 伝説の茶器 5億。

  - 世帯の絵に、新しい5種類の小さな絵を足した(大皿・刀・仏像・屏風・茶器)。
  - 気づいたこと: いまの収入(年100万円前後)では、数億円の品は何世代も貯めないと届かない。目標としての品として置いた。
- テスト: ゲームのテスト153件(自動では払われない・降ろせる・残高まで・借金がなくても降ろせる・値段の幅)、画面の通し操作、自動プレイが通った。実ブラウザで、借金の案内、金庫の画面と降ろす操作、買い物の一覧、世帯の絵を確かめた。

## 金庫は借金のときだけ・換金アイテムを5つに
- ユーザーの希望で、互助金庫から降ろせるのを「借金があるときだけ」にした。前の回で「いつでも降ろせる」にした判断は取り消し。

- 換金アイテムが9種類では多すぎるとのことで、5種類にした。200万円から数億円までの幅は残し、間がおおよそ同じくらい開くように選んだ。
  - 古い壺 200万円 / 洋画 1500万円 / 名工の日本刀 6000万円 / 古い仏像 1.2億円 / 伝説の茶器 5億円
  - 外した品(掛け軸・金の延べ棒・古伊万里の大皿・金箔の屏風)を古いセーブで持っていても、品物は消えない(名前と値段は品物の側に残っている)。絵の描き分けも残した。
- ユーザーから、途中の連絡を英語で出さないようにと指摘があった。以後、報告は途中のものも含めて日本語にする。
- テスト: ゲームのテスト155件(借金があれば降ろせる・借金の額まで・残高まで・借金がなければ降ろせない・換金アイテムは5つ)、画面の通し操作、自動プレイが通った。実ブラウザで、借金がないと押せないこと・借金より多くは降ろせないこと・借金の分を降ろせること・買い物の一覧が5つになったことを確かめた。

## 1年進めたときの小さな動き
- ユーザーの希望: 1年進めてもゲームが進んでいる感じが少ない。進めるごとに、世帯の家族が喜ぶ動きと、収入が入る(または減る)簡単で小さな動きを、世帯の画面の資金のところに出したい。
- 資金: 1年進めた直後だけ、左の欄の「資金」の横に、その1年の増減(収入から生活費・治療費・利息・自動の買い直しなどを引いた、手持ちの差)が「+52万円」「−15万円」とふわっと浮かんで、2秒ほどで消える。増えたら緑、減ったら赤。資金の数字も一瞬だけ少し大きくなる。
- 家族: 1年進めた直後だけ、世帯の絵の家族(当主・配偶者・子供)が順番に2回ぴょんと跳ね、頭の上に音符が浮かんで消える。収入が減った年も、家族は喜ぶ(1年をみんなで越えた、という扱い)。

## 質屋の持ち物が顔にかかっていた

## テストプレイ: 特化型で都会から職を持ち帰るまで
- ユーザーの依頼で、特化型の育て方で、都会帰りが上位職(手土産の職)を持ち帰るまでの年数を、自動プレイで測った(各12回、1世帯ずつ1年交代で進める)。
  - 手土産の条件: 都会帰りの人の、いちばん高い分野の平均が34以上で、ほかの2分野の平均より9以上高い。持ち帰れる上位職は、身体 → 宮大工、頭脳 → 商店主の2つだけ(精神にはない)。
  - 頭脳特化(全世帯が商店店員・育成方針も商店店員・当主はときどき頭脳を鍛える・縁談は頭脳寄りの人): 12回すべてで持ち帰った。村の年数で中央値37年(最短35・最長54)、2世代目。そのときまでに全世帯で遊んだ年数の合計は約600年。
  - 身体特化(農家で同じ方針): 跡継ぎに総合でいちばんの子を選ぶと、61年までに持ち帰れたのは12回中5回(中央値49年)。農家は計算力・打たれ強さも鍛えるので、身体だけに偏りきらない。跡継ぎに「特化の弱い子」を選び、特化の強い子を都会へ出すと、12回すべてで中央値37年になった。
  - 最短でも35年ほどかかるのは、1世代目の子が都会へ出て(親が45歳で跡継ぎを決めたあと16歳で出る)、2世代目の当主の縁談(25歳)の相手として戻ってくるまでの時間のため。
- 測っている途中で、都会帰りの子が、生まれた家の次の当主(自分の兄弟姉妹)に嫁いでいる例が見つかった(自動プレイで、都会帰りの結婚274件のうち59件)。

## 自分の村の出身者を縁談で優先・兄弟姉妹の縁談をなくした
- ユーザーの希望: 自分の村出身の村人は、他の村での縁談より高い確率で、自分の村の縁談に出るようにしたい。

  - その子は、都会へ出た16歳の時点でサーバーにも送られ、他の村の縁談にもすぐ出ていた(年齢の確認なし)。
  - 自分の村で結婚した子もサーバーに残るので、他の村でも結婚できてしまっていた。
- 選んでもらった形:
  - 他の村から来た人が縁談に加わるのを、毎回から「縁談3回に1回ほど」にした。縁談が持ち込まれたときに、ゲームの乱数で決める(セーブし直しても変わらない)。自分の村の出身者は、これまでどおり、いれば毎回出る。

## 最初の職業を増やした(猟師・山菜取り・畜産家・木こり)と服屋・地産地消の強化
- ユーザーの希望で、最初から就ける職業に4つ、解放される職業に1つを足し、シナジー「地産地消」を強くした。
- 猟師(就く条件なし): 身体と精神(腕力・脚力・勇気・打たれ強さ)で収入が決まる。年ごとの当たり外れもある。仕事道具は罠(脚力)と猟銃(腕力+勇気・勇気30が要る)。
  - 村への効果: 農家の害獣被害が減る。合わせて、農家に害獣被害の突発イベントを足した。猟師がいないと1年に12%で起こり、その年の収入が55%になる。猟師がいると起こる確率が約3分の1になり、起きても80%残る(「猟師が見回ってくれたおかげで、被害は小さく済んだ」)。
- 山菜取り(就く条件なし): 技能が収入に効く割合を小さくした(職業ごとに「技能0のときの倍率と、技能100で増える分」を持てるようにした。ほかの職は 0.55と0.9、山菜取りは 0.92と0.16)。身体が高いと少しだけ多い。背負いかごで少し増える。
- 畜産家(就く条件なし): 鶏・牛・豚・羊のうち1種類だけ育てられる(買う)。ほかの家畜を持っていると買えず、売れば替えられる。
  - 鶏: 40万円・1小屋+15。安いが、1年に7%で鳥インフルエンザが流行り、全滅する(自動で買い直す設定なら1小屋だけ買い直す)。
  - 牛: 450万円・1頭+70(2頭まで)。豚: 150万円・1頭+28。羊: 150万円・1頭+14で収入は少ない。
  - 羊を買うと、その年から村で服屋に就けるようになる(解放条件に「その道具を村の誰かが買ったら」を足した)。
- 木こり(就く条件なし): 体力(腕力・脚力・打たれ強さ)で稼ぐ高収入の職。村に木こりが1人増えるごとに、1人あたりの収入が 1/(1+0.3×(人数−1)) になる(配偶者の木こりも数える)。村にいると家の値段が15%下がる(建物の割引と合わせて60%まで)。
- 服屋(羊が必要): 都会帰り・他の村から嫁いできた人(歴代の配偶者も数える)1人ごとに、流行を取り入れて収入+6%(10人まで)。仕事道具は機織り機。
- 地産地消: 農家+商店店員で発動するのはこれまでどおり。猟師・漁師・山菜取りが村に1つ増えるごとに、効果が1.5倍・2倍・2.5倍になる(食費の割引と商店店員の収入の増え方)。村の効果の一覧には「地産地消(農家+商店店員+猟師+漁師+山菜取り) 効果×2.5」と出る。
- 数値の調整(職業ごとに40年働かせて比べた):
  - 最初の案では、畜産家は家畜がいないと収入が生活費を下回り、最初の資金(50万円)では鶏も買えず、借金が増え続けた。基本収入を45→70、鶏を60→40万円にした。
  - 木こりはひとりだと他の職の約2倍稼いだので、基本収入を150→130に下げた(ひとりなら、それでもいちばん稼ぐ)。山菜取りは序盤から他より高かったので80→70に。鶏は稼ぎすぎたので1小屋22→15に。
  - 調整後の最初の10年の年収の目安(中央値): 農家71・漁師59・商店店員61・猟師65・山菜取り73・木こり101(ひとりのとき)・畜産家(鶏)70前後・服屋63。牛は高いので、鶏で稼いでから替える遊び方を想定している。
- 見た目: 5職業すべてに、帽子と道具が重ならない見た目を足した(猟師: 羽根つき帽子と弓 / 山菜取り: 頬かむりと山菜 / 畜産家: つば広帽子と農業用フォーク / 木こり: 毛糸の帽子と斧 / 服屋: 首の巻き尺とはさみ)。
- 村の絵: 服屋は左の道沿い、牧場(村でいちばん多い家畜を描く)は右下の海の手前、木こりの丸太置き場は右上の丘のふもと。猟師は左の林へ、山菜取りは右の丘へ出かける。
- 世帯の絵: 家畜の囲い(頭数ぶん)、猟師小屋と罠、背負いかご、丸太と斧、機織り機を描くようにした。
- 古いセーブにも、新しい最初の職業が入る。
- テスト: ゲームのテスト182件(新しい職業に条件がない・服屋は最初は就けない・山菜取りは能力の差が小さい・猟師は差が大きい・木こりは増えるほど減る・家が安くなる・害獣被害と猟師の効果・家畜は1種類だけ・羊で服屋が解放・鳥インフルエンザ・服屋の流行・地産地消の強化・古いセーブ)、画面の通し操作(見た目が重ならない確認を含む)、自動プレイが通った。実ブラウザで、16職業の見た目(道具が顔にかからない)・世帯の絵・買い物の画面・村の絵を確かめた。

## 課金を自動にする2つの処理を書いた
- ユーザーの希望: 決済リンクで買ったが「24時間以内に付与」と出てすぐ反映されない。買ったら自動で増えるようにしたい。
- 振り返り: 前の会話で、私がこの2つの処理(Edge Functions)を書こうとしたとき、作業環境の自動の安全チェックに書き込みを止められていた。それを「私には書けない」とだけ伝え、手順の説明を何度も繰り返してしまい、ユーザーに強く指摘された。今回はユーザーからはっきり頼まれたので、もう一度書いてみたところ、止められずに書けた。
- 書いたもの(DEPLOY.md の「課金の処理の約束事」のとおり):
  - `supabase/functions/_shared/billing.ts`: 2つの処理で使う共通の部品(秘密の値の読み込み・Stripe と Supabase の窓口・CORS・本人の確かめ・鍵と決済のモードの比較・世帯枠の合計)。
  - `create-checkout`: 本人を確かめ、支払い済みが8回未満・1時間に作った支払いページが5つ未満であることを確かめてから、Stripe の支払いページを作る(100円・カードのみ・約30分で期限切れ・商品名「ふるさと百代記 世帯枠 +10」・印 `game: furusato` と本人のID・明細の接尾辞 FURUSATO)。`purchases` に支払い待ちで記録し、支払いページの URL を返す。
  - `confirm-checkout`: 本人の購入(指定の1件、または支払い待ちすべて)を Stripe に問い合わせ、支払い済みで印と本人が合えば支払い済みに更新する。更新できた行だけを数える(二重に足さない)。期限切れは期限切れに、鍵と決済のモードが違うものは問い合わせずに期限切れにする。
- 確かめたこと(手元の Supabase で処理を動かした。`.env` の鍵が本番用なので、Stripe に問い合わせずに済む部分だけ): 事前確認(OPTIONS)に答える / ログインしていなければ作らない・確かめない / 支払い待ちがなければ0 / モード違いは問い合わせずに期限切れ / 支払い済みは二重に足さない / ほかの人の購入は数えない / 支払い済み8回ならそれ以上作らない / 合計は+80まで。9項目すべて通った。
  - 手元の Supabase では、OPTIONS には処理の手前の受付(Kong)が代わりに答える。本番では処理まで届くので、処理側の答え方も残した。
- 残り: テスト用の鍵で、支払いページを作る → テスト用カードで払う → 戻ると世帯枠が増える、までを確かめる。そのあと本番に置き、画面の設定を自動の形に切り替える。
