## 都会へ送る子の能力の上限を「合計」で見るように変更

### ユーザーとのやりとり
- ユーザーから「ずる対策が分からない」と質問があった。想定しているのは次のずる。
  - このゲームの計算はブラウザで動いているので、開発者ツールでセーブや送るデータを書き換えられる。
  - 自分の村だけなら本人が損をするだけだが、他の村との行き来が入ったので、書き換えた「全能力100の子」が、まじめに遊んでいる他のプレイヤーの縁談に流れてしまう。
  - 迎えた村は、遺伝や手土産でバランスが崩れる。
- あわせて「特化型ビルドが損をしないようにしたい」という要望があった。

### 問題だった点
- これまでは、能力の1つ1つに上限をかけていた(10世帯の組はどれも40まで)。そのため、合計は少ないのに1つが高い特化型ほど削られていた。

### 何を更新したか
- 上限を、6つの能力の**合計**で見るように変えた(`supabase/migrations/20261101000000_city_cap.sql`)。
  - 合計が上限以内なら、配分はそのまま通す。
  - 超えたときだけ、全部を同じ割合で縮める(どこに特化しているかの形は残る)。
  - ありえない値をはじくため、1つの能力にも、ゆるい上限だけは残した。
- 上限: 10世帯の組は合計220・1つ80、20世帯の組は260・90、30世帯以上は300・100。

### 上限の決め方(計測)
- 自動プレイで育てた子(30世帯の組): 合計は中央値142・95%が158以下・最大165、いちばん高い能力の最大は45。
- 極端に特化させた子: 強く偏った両親・立派な家・16年同じ方向に育成し、開花と都会での伸びを最大にした場合。合計は最大292、1つの能力の最大は83。
- この極端な特化型でも、30世帯以上の組なら削られない値にした。全部100に書き換えた子(合計600)は、確実に削られる。

### 検証
- データベースのテスト34件が通った。追加・変更したテストは次のとおり。
  - 特化型(腕力90→80、ほかはそのまま)は削られない
  - 全部100は合計220まで同じ割合で縮む
  - 合計を超えた特化型は、偏りの形を保ったまま縮む
- 本番の Supabase には、この定義と前日の「都会」の定義を、ユーザーが `supabase db push` で入れる。

## 世帯の絵・縁談の顔ぶれ・遠い親戚・家系図
### 何を更新したか
- **世帯の絵**: 世帯を開くと、村の様子と同じ手書き風の絵が上に出る。
  - 家: 格によって見た目が変わる。
  - 家族: 当主・配偶者・子供。子供は年齢で大きさが変わり、家の前を歩き回る。
  - 仕事道具: 農地(収穫できる区画は作物、超えた分は休ませた畑)、農業機械、漁船と海、漁網、店、大工の作業場、炉、画材、質屋の蔵、教材、診療器具。使っていない職の道具は箱。
  - 換金アイテム、収集品(宝箱と個数)。
- **縁談は4人**: ふつうは村の外の人4人。他の村から来た人がいれば、村の外の人1人と入れ替えて 3+1。自分の村の出身者もいれば 2+1+1。他の村の人・自分の村の出身者は、それぞれ1人まで。
- **遠い親戚**
  - 子が生まれるときに、両親の血筋とこの村・この家を受け継ぐ(血筋は12件まで)。
  - 都会へ送るときに、血筋とその子の番号も送る。
  - 他の村から迎えた人がこの村の血を引いていれば、「〇〇は△△家の遠い親戚だった！」の演出が出て、収集品「△△家の家系図」を持ってくる。収集のランキングにも数える。
- **家系図**: 「歴代の当主」に「家系図を見る」を付けた。
  - 各世代の当主・配偶者(どこの家から来たか)・子供全員と、子供の行き先(跡継ぎ / この村の〇〇家へ / 〇〇村の〇〇家へ / 都会で暮らしている / 今の年齢)を表示する。
  - 他の村での結婚は、便りが届いたときに、送った子の番号で家系図に書き込む。
- **データベース**(`supabase/migrations/20261102000000_city_roots.sql`): 都会の表に「血筋」と「送り出した村での番号」の列を足した。送る・引く・結婚する・便りの関数を、それを扱う形に作り直した。血筋は、形の違うものを捨て、文字列の長さをそろえ、12件までにする。

### 設計メモ
- 「大きくなりすぎないか」というユーザーの心配について。1つの家で記録するのは、各世代の当主と、その世代の子供の番号だけ。子供の詳しい情報は、もともと持っている都会の記録から引くので、何十世代でも軽い。
- 他の村に嫁いだ子の、その先の子孫は追わない(他のプレイヤーのデータのため)。その代わりに「遠い親戚」の仕組みで、何世代かあとに血がつながった形で戻ってくる。
- 村ごとに識別子(`village.uid`)を持たせた。村の名前は重なることがあるので、血筋の比較にはこちらを使う。
- 古いセーブ: 世代交代の記録に子供の情報がない世代は、跡継ぎだけを表示する。

- 決めたこと:

  - 方向は世帯に1つで、子供全員に共通(「子供を育てる」が子供全員をまとめて育てる仕組みなので、それに合わせた)。2人目・3人目が生まれたときも画面は出るが、今の選択に札が付いて一番上に出るので、変えないならそのまま選べる。

  - 縁談・跡継ぎの決定が出ているときは、そちらを先に出す。セーブの読み込みや世帯の切り替えのあとでも、まだ選んでいなければ画面が出る。

## 嫁いできた人が、元の職業のまま村で働く
- ユーザーの希望: 自分の村の出身・他の村の出身の人が嫁いできたら、元の職業を引き継ぎ、その収益と村への効果も持ち込む(大工なら、村に大工がいることになる)。代替わりのときには、ほかの村人と同じように引退させる。
- 決めたこと(ユーザーに確かめた):
  - 都会へ出た子は、いままでゲーム上で職に就いていなかった。「元の職業」は、生まれた家で育てられた職業(育成方針でいちばん鍛えられた職のうち、就く条件を満たすもの。なければ能力のいちばん合う職)にした。都会へ出るときに決めて、本人に持たせる。
  - ごく稀に、都会帰りの手土産で新しい職業を持ち帰ったときは、職の解放だけでなく、本人もその職で嫁いでくる(上位職の手土産も同じ扱い)。
  - 収入は、その職の基本収入を本人の技能で計算した**半分**(家事・子育ても担うため)。仕事道具・昇進はなし(当主の道具は当主の職のためのもの)。当主の行動(自分を高める年など)に関係なく、毎年働く。記録には「収入 91万円(うちサキの稼ぎ 35万円)」と出す。
  - 村の外の人(NPC)は職を持ち込まない。
- 村への効果: その職業は、結婚した年から村にあることになる(時間差の仕組みどおり、結婚より前の年の世帯には効果がない)。村に初めての職なら「村に初めての〇〇」の出来事にも残る。代替わりで引退すると、その職の効果はなくなる(当主の職と同じで、いま働いている人の職だけが効果を出す)。
- 他の村から来る人: 送り出した村の側で職業を決めてサーバーに一緒に送るように、データベースに「職業」の欄を足した(`20261103000000_city_job.sql`)。形の違う値(英小文字と _ 以外)はサーバーで捨てる。迎えた村にまだない職業(医者など)だったら、能力から村にある職を選び直す(他の村との行き来で、職の解放ができてしまわないように)。
- 画面: 縁談の候補に「職業: 大工 — 嫁いだあとも村で働き…(収入は基本の半分)」、世帯の左の欄の配偶者に「村出身・大工 年35万円」、家系図の配偶者に職業を出す。
- 迷ったこと: 嫁いできた大工が施設を建てられるようにするかは、今回は入れていない(施設の建設は当主の行動のまま)。村の様子の絵にも、配偶者の仕事場はまだ描いていない。
- 気づいたこと(お金): 自動プレイで比べると、世帯の所持金の中央値が約2.4倍、互助金庫が約3倍に増えた(自動プレイは都会帰りを優先して選ぶので、ほとんどの世帯に稼ぎ手が2人いる)。都会帰り・他の村の人と結婚する理由としては強い。重すぎるようなら、半分の割合(`SPOUSE_SHARE`)を下げて調整する。
- 古いセーブで、すでに結婚している配偶者には職業を付けていない(公開前なので、さかのぼっては変えない)。
- テスト: ゲームのテスト149件(職業の決まり方・効果が出る年・収入が半分・代替わりで引退・村の外の人は職なし・他の村の職業と、村にない職のとき・手土産の職)、データベースのテスト39件(職業が届く・形の違う値を捨てる)、画面の通し操作が通った。実ブラウザで、縁談の候補・配偶者の欄・収入の記録を確かめた。
- ユーザーの作業: 本番のデータベースに `supabase db push` で今回の定義を入れる必要がある(入れる前に新しい画面を公開すると、他の村へ子を送るのに失敗し続ける)。

## 互助金庫は自分で降ろす・換金アイテムの値段の幅を広げた
- ユーザーの作業: 本番のデータベースへの `supabase db push`(配偶者の職業の欄)が終わった。
- 互助金庫:
  - ユーザーの希望で、所持金がマイナスになっても、金庫から自動で払われないようにした。代わりに、自分で降ろせるようにした。
  - 「互助金庫に納める」のボタンを「互助金庫」にして、同じ画面で「納める / 降ろす」を選べるようにした。年には数えない。
  - 降ろせるのは残高まで。借金がなくても降ろせる。金庫は村のみんなのお金(どの世帯・どの年からでも使える)という、これまでの考え方に合わせた。
  - 迷ったこと: 「借金があるときだけ降ろせる」にする案もあった。ただ、世帯はすべて同じプレイヤーのもので、納めたお金を別の世帯で使うのが金庫の役目なので、制限はつけなかった(納めたことで名士になる特典なども、いまはない)。
  - 借金がある間は、毎年5%の利息がつく(これまでは金庫が空のときだけだった)。記録の利息の行に「互助金庫から降ろして返すこともできる」と添える。世帯の画面にも「借金が120万円あります…[互助金庫を開く]」と出す。
  - 金庫の画面では、借金があるときは金額の欄に借金の額を最初から入れておき、「借金の分」のボタンも出す。
  - 自動プレイは、借金ができたら自分で降ろして返すようにした(人が遊ぶときと同じ)。
- 換金アイテム:
  - ユーザーの希望で、100〜300万円の4種類から、200万円〜5億円の9種類にした。古い壺 200万 / 掛け軸 400万 / 金の延べ棒 800万 / 洋画 1500万 / 古伊万里の大皿 3000万 / 名工の日本刀 6000万 / 古い仏像 1.2億 / 金箔の屏風 3億 / 伝説の茶器 5億。
  - 高いものほど値上がり(年3〜6%)と成長の補正(0.8〜3%)が大きい。補正の合計の上限(12%)はそのままにしたので、高い品を並べても成長が際限なく伸びることはない。
  - 世帯の絵に、新しい5種類の小さな絵を足した(大皿・刀・仏像・屏風・茶器)。
  - 気づいたこと: いまの収入(年100万円前後)では、数億円の品は何世代も貯めないと届かない。目標としての品として置いた。
- テスト: ゲームのテスト153件(自動では払われない・降ろせる・残高まで・借金がなくても降ろせる・値段の幅)、画面の通し操作、自動プレイが通った。実ブラウザで、借金の案内、金庫の画面と降ろす操作、買い物の一覧、世帯の絵を確かめた。

## 金庫は借金のときだけ・換金アイテムを5つに
- ユーザーの希望で、互助金庫から降ろせるのを「借金があるときだけ」にした。前の回で「いつでも降ろせる」にした判断は取り消し。
  - 降ろせるのは借金の額まで(残高の範囲で)。借金があるときに大きく降ろして、別の使い道にまわすことはできない。
  - 借金がないときは、金庫の画面の「降ろす」ボタンを押せないようにした。借金より多い額を入れると「降ろせるのは借金の額(120万円)までです」と出る。
- 換金アイテムが9種類では多すぎるとのことで、5種類にした。200万円から数億円までの幅は残し、間がおおよそ同じくらい開くように選んだ。
  - 古い壺 200万円 / 洋画 1500万円 / 名工の日本刀 6000万円 / 古い仏像 1.2億円 / 伝説の茶器 5億円
  - 外した品(掛け軸・金の延べ棒・古伊万里の大皿・金箔の屏風)を古いセーブで持っていても、品物は消えない(名前と値段は品物の側に残っている)。絵の描き分けも残した。
- ユーザーから、途中の連絡を英語で出さないようにと指摘があった。以後、報告は途中のものも含めて日本語にする。
- テスト: ゲームのテスト155件(借金があれば降ろせる・借金の額まで・残高まで・借金がなければ降ろせない・換金アイテムは5つ)、画面の通し操作、自動プレイが通った。実ブラウザで、借金がないと押せないこと・借金より多くは降ろせないこと・借金の分を降ろせること・買い物の一覧が5つになったことを確かめた。

## 職に就いている配偶者の見た目
- ユーザーの希望で、配偶者が職に就いている(村の出身・他の村から嫁いできた人)ときは、その職の見た目で描くようにした。
- 世帯の絵: 配偶者を、当主と同じく職業ごとの服の色・帽子・道具で描く(大工なら、はちまきと金づち)。名前の札にも「サキ(22歳)・大工」と職業を出す。職のない配偶者は、これまでどおりの普段着。
- 村の絵:
  - 職に就いている配偶者も、その職の格好で村を歩き、仕事場へ働きに出る(これまで村の絵には配偶者を描いていなかった)。
  - 村の絵で「その職業の人がいるか」を数えるときに配偶者の職業も数えるようにしたので、配偶者だけが大工の村にも大工の作業場が建つ(村の効果の仕組みと合わせた)。
- 迷ったこと: 世帯の絵の右側の仕事場は、当主の仕事道具(買ったもの)を描く場所なので、道具を持たない配偶者の仕事場は足していない。
- ゲームのテスト155件と画面の通し操作が通った。実ブラウザで、当主が農家・配偶者が大工の世帯の絵と、村の絵(大工の作業場が建ち、配偶者が大工の格好で歩く。職のない配偶者は村の絵に出ない)を確かめた。
